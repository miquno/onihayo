# Threat model

- Last reviewed: 2026-10-08 (0.9 account authentication and email-link boundary)
- Update this document in the same pull request whenever a trust boundary, data category, third-party service, or externally reachable endpoint changes.

## System today (0.9 account foundation)

A single SvelteKit server (Node, `adapter-node`) behind a TLS-terminating reverse proxy renders public lessons and practice, serves static assets, and exposes `GET /healthz`. Public content is bundled and validated. Guest progress and review state remain in validated browser storage; typed answers are never sent to the server. The optional account routes (`/account`, `/account/confirm`, `/account/recover`) accept email and one-time link input. When `AUTH_ENABLED=true`, the server uses a restricted PostgreSQL role for account, link, session, and rate-limit records, and sends plain-text links through Amazon SES in `eu-central-1`. The feature defaults off and must remain off publicly until the provider, retention, deletion, and production database controls are ready. Signing in does not sync progress. Account routes send no-store responses and a no-referrer policy; the proxy must redact confirmation query strings from access logs. Browser pages make no third-party requests. SvelteKit's client router keeps per-tab scroll positions in `sessionStorage`.

## Actors

- **Anonymous Internet user** — can send arbitrary HTTP requests. The default adversary.
- **Malicious or compromised learner account** (from 0.9) — authenticated, tries to reach other users' data or abuse endpoints.
- **Automated abuse** — credential stuffing, sign-up spam, scraping, request floods.
- **Supply-chain attacker** — publishes a malicious package version or compromises a GitHub Action.
- **Malicious contributor** — submits a pull request that weakens CI, headers, or content integrity.
- **Hosting provider / operator error** — misconfiguration, leaked secrets, lost backups.

## Privacy threats

- **Third-party tracking.** No analytics, ads, tag managers, social embeds, external fonts, or CDNs; CSP blocks third-party origins.
- **Over-collection.** Data ownership rules ([data-ownership.md](../architecture/data-ownership.md)) require every stored field to have a purpose.
- **Log leakage.** Logs exclude personal data and secrets; retention is short.
- **Account identifiers.** A confirmed account stores normalized email and verification timestamps. Pending link rows hold the requested email, token hash, purpose, and timestamps. Rate-limit rows hold keyed digests of IP/email and counters, never raw identifiers. Expired rows are pruned on later authentication activity; periodic retention cleanup is required before public activation. Session rows hold a token hash, user ID, and expiry timestamps. Guest progress remains local.
- **Email provider.** When enabled, SES receives the recipient email and plain-text account link through its Frankfurt endpoint. The message contains no pixel or tracked URL. The owner must review SES processing terms, retention, transfers, sender domain, and least-privilege credentials before activation.
- **Link leakage.** The one-time bearer appears in the emailed confirmation URL and browser history until used. Account pages set `Referrer-Policy: no-referrer` and `Cache-Control: no-store`; proxy access logs must strip query strings. The link is consumed by POST only, so link previewers cannot use it merely by fetching it.
- **Deletion and backups.** Self-service account deletion, data export, production backup retention, and periodic cleanup are later 0.9 items. Keep public account sending disabled until these controls and the production privacy notice are complete.

## Accepted risks

- Static assets served by adapter-node do not pass through SvelteKit hooks; the reverse proxy must add baseline headers. If the proxy is misconfigured, only the defence-in-depth headers on static files are lost; the CSP-protected documents are unaffected.
- The CSP allows exactly one inline `style` attribute value by hash (`'unsafe-hashes'` in `style-src-attr`), for SvelteKit's screen-reader route announcer. Inline styles cannot execute script.
- `cookie@0.6` (via SvelteKit) has a low-severity advisory that only applies when untrusted input is used as a cookie name, path, or domain. The session cookie's name and path are constants and Domain is absent. Recorded in [dependencies.md](dependencies.md).
