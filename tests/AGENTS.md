# tests/

Browser tests. Unit tests do not live here; they sit next to the code in `src/` as `*.test.ts`.

## Map

- `e2e/foundation.spec.ts` — the production server's baseline: landing page renders without console errors (which also catches CSP violations), axe WCAG 2.2 A/AA scan in light and dark mode, security headers, friendly 404 handling, cross-origin form rejection, and `/healthz`.
- `e2e/licences.spec.ts` — the Licences page lists every package found in the final `build/` output's source maps (including what the adapter adds after Vite), and licence texts open with the keyboard and wrap at 320 px.
- `e2e/hiragana.spec.ts` — the hiragana lessons journey: header → lesson list → every lesson in order through "Next lesson" and back, keyboard only; kana marked `lang="ja"`; unknown lessons answer with the friendly 404 page. Practice: lesson → practice → summary with the keyboard only (blank-answer hint, miss with the correct answer in the live region, an accepted alternative, no network requests while answering, focus on the results, "Practise again"); the same seed gives the same order; the whole practice with buttons alone. Milestone 0.3 acceptance: from the home page's Continue action through every lesson and its practice to the end, keyboard only. Chart: reached from the lesson list with the keyboard; tables named by their headings, column and row headers, cells in the right row and column, all 104 characters marked `lang="ja"`.
- `e2e/katakana.spec.ts` — the katakana lessons journey: from the last hiragana lesson and from the header, through every lesson in order with the keyboard only, the look-alike and mark (ー, ッ) sections exactly where they are taught, シ/ツ told apart in the T row, kana and example words marked `lang="ja"`, the 404 for unknown lessons, a lesson practised with the keyboard only (a miss, an input-method alternative, no network requests, next lesson from the results), the same seed giving the same order, the katakana chart's table semantics with all 116 katakana, and milestone 0.4 acceptance: every katakana lesson and its practice, keyboard only.
- `e2e/words.spec.ts` — vocabulary lessons and word detail pages; tests both meaning-to-reading and reading-to-meaning practice, completion persistence, and the link to the next lesson.
- `e2e/quiz.spec.ts` — the kana quiz: from the header with the keyboard only, rows of both scripts chosen with Space, the "All" switch (including its mixed state) and the live count, a full quiz to the results without network requests, "Change selection" keeping the rows; starting with nothing selected explained; unknown rows redirected to the selection; the same seed gives the same order. Type-the-kana mode (`?mode=type-the-kana`): kana typed for romaji, the usual kana accepted for a rare one that reads the same, half-width katakana accepted, and Enter during a real input-method composition (driven through the DevTools protocol) not submitting. Practice setup: mode and length chosen with the keyboard, then a choose-the-character quiz to the results (four same-script options, a wrong and a right choice, focus on "Next" and on the first option, no network requests, "Change selection" keeping mode, length, and rows), a type-the-kana quiz, an endless quiz ended with "Finish", and the same seed giving the same options. Choice keyboard support: a number does nothing without focus on an option, arrow keys, Home, and End move and wrap, a number answers, numbers do nothing after the answer, and a whole quiz with numbers and Enter alone. Results: accuracy, time, mistakes ordered by misses, "Retry mistakes" asking only the missed kana twice each (typed, and in a choice mode after an endless quiz), no retry without mistakes, and "Practise again" restoring the whole selection.
- `e2e/layout.spec.ts` — for every page and error route in its `pages` list: shell landmarks, one `h1`, page title, correct `aria-current` state in the header and footer navigation, no requests to other origins, no console errors (which catches CSP violations), no cookies, and no local progress writes on a simple page visit (SvelteKit may keep its own `sessionStorage` scroll keys), skip link moving focus to `main`, no horizontal overflow at 320, 768, 1280, and 1440 px and at 200 % zoom, and axe in light and dark mode. Also the keyboard tab order on the home page.
- `e2e/progress-storage.spec.ts` — corrupt stored progress is quarantined and shown as a learner-facing notice; a newer document is left untouched and asks the learner to reload.
- `e2e/progress.spec.ts` — lesson outcomes and completion persist, home continues to the next lesson, Settings exports and imports into a fresh browser, rejects invalid/oversized files, and resets after confirmation.
- `e2e/reviews.spec.ts` — the home page puts actionable due reviews before the next lesson; scheduled kana and vocabulary use the shared review session and persist scheduler ratings; Settings persists the daily cap and new-lesson target.

## Rules

- E2E tests cover important user journeys and cross-cutting guarantees only (headers, accessibility, critical flows). Logic is tested with unit tests.
- Tests run against the real production build (`pnpm build && node build`), started by `playwright.config.ts`.
- Every new page route is added to the `pages` list in `e2e/layout.spec.ts`, which gives it the axe, keyboard, and layout checks.
- Query by role, label, or text — what a user or screen reader perceives — not by CSS classes.
- No arbitrary sleeps. Use Playwright's auto-waiting assertions.
- Tests must be deterministic: fixed seeds and injected clocks where randomness or time is involved.
- If the local Chromium does not match the Playwright version, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to a Chromium binary instead of changing versions. CI installs the matching browser.
