# src/lib/content/

Onihayo's learning content as typed, versioned data ([ADR 0003](../../../docs/decisions/0003-content-as-versioned-data.md)). Plain TypeScript: imports neither `svelte` nor `$app/*`, and does no I/O. Provenance and licensing rules: `docs/content/`.

## Map

- `model.ts` — the content model: `ContentOrigin`, dataset `Provenance`, the kana types (`KanaRecord`, `KanaScript`, `KanaClass` with the katakana-only `extended` class, `kanaRows` in order: the gojūon rows, then the extended katakana rows, and `scriptRows`, the rows each script has), and `KanaLesson` (rows taught together, with a pronunciation note, notes for individual kana, optional `MarkNote`s for spelling marks such as ー and ッ, each with `MarkExample` words, and optional `LookAlikeNote`s that tell apart two or three look-alike kana by item ID).
- `lessons.ts` — lesson helpers: `lessonSlug()` (URL segment from the lesson ID), `findLesson()` (exact slug match only), `nextLesson()`, `lessonKana()` (the kana of a lesson's rows in dataset order), and the page data both scripts' lesson routes load: `lessonSummaries()` (the lesson list) and `lessonDetails()` (one lesson page with look-alikes resolved to characters and romaji, `undefined` for an unknown slug). Tested in `lessons.test.ts`.
- `selection.ts` — choosing kana by row across scripts for the kana quiz: row keys (`hiragana.ka`, `katakana.kya`), `parseRowSelection()` (keeps only known keys from untrusted URL values, once each, in display order), `rowSelectionSearch()` (the `?rows=` query string), `selectedKana()`, and `rowsByClass()` (a script's rows grouped by class, leaving out classes it does not have). Row keys come from `scriptRows`, so every key selects kana. Tested in `selection.test.ts`.
- `chart.ts` — `kanaChart()`: the gojūon grid of one kana class for the chart page. A kana's column is the vowel its romaji ends in (ya/yu/yo for yōon), empty positions are `null`, and a row whose only kana ends in no vowel (ん) spans the row. `chart.test.ts` pins the grids and checks that the three charts show every hiragana once.
- `kana/` — Onihayo-authored kana data under CC BY-SA 4.0 (`kana/LICENSE`). `hiragana.ts`: the 46 basic hiragana, 25 with dakuten/handakuten, and 33 yōon, in gojūon order, with the dataset's `provenance`. `katakana.ts`: the same 104 sounds in katakana, in the same order with the same readings and alternatives, then 12 extended katakana for loanwords (ティ ディ ファ フィ フェ フォ ウィ ウェ ウォ シェ ジェ チェ, one row per consonant sound), and its own `provenance`. `hiragana-lessons.ts`: 18 lessons (one per row, わ/を/ん together, three for yōon) with authored English pronunciation notes and their own `provenance`. `katakana-lessons.ts`: 20 lessons on the same rows plus two for the extended katakana, with the long vowel mark ー taught in the K row and the small ッ in the T row, look-alike notes (シ/ツ, ソ/ン, ク/ケ, ク/タ, チ/テ, ス/ヌ, ア/マ, コ/ユ, ル/レ, ウ/フ/ワ) in the lesson that teaches the last kana of each set, and their own `provenance`.
- `hiragana.test.ts` — what the data says: the hiragana inventory, readings, accepted alternatives, ID scheme, and origin.
- `katakana.test.ts` — the same for katakana: the inventory per class, that everything but the extended class spells exactly the sounds of hiragana (same order, rows, classes, readings, alternatives, and IDs apart from the script), and the extended class's readings, alternatives, and IDs.
- `kana-dataset.test.ts` — dataset validation, run for each script: exact counts per class (hiragana has no extended kana), unique IDs and characters (a precomposed kana of that script, followed by a small ya/yu/yo for yōon or a small vowel for extended katakana), non-empty lowercase romaji, no duplicate alternatives, complete rows in order within one class, exactly the rows of `scriptRows`, and an origin on every record. Also that no ID or character appears in both scripts.
- `kana-lessons.test.ts` — lesson validation, run for each script: the lessons teach every kana of the script exactly once in dataset order, exactly the script's rows in order, IDs named after the script and first row, one kana class and 3–12 kana per lesson, plain-text titles and notes, kana notes only for kana the lesson teaches, mark examples written only with kana and marks taught up to their lesson, and look-alike sets of two or three kana, in teaching order, all taught by their lesson and at least one in it, each set once. Also where katakana teaches ー, ッ, and the look-alikes the roadmap names.

## Rules

- A content directory holds content only, under the single licence in its `LICENSE` file. Types, helpers, and tests are code (MIT) and live outside it, here in `src/lib/content/`.
- Onihayo-authored content directories carry the CC BY-SA 4.0 legal code as `LICENSE` ([ADR 0006](../../../docs/decisions/0006-code-and-content-licensing.md)). Imported data keeps its own licence and follows the import checklist in `docs/content/README.md`.
- Every record has a stable ID (`kana.hiragana.shi`, `kana.katakana.shi`) that is never renamed or reused, because learner progress refers to it, and states its `origin` (`imported`, `generated`, or `authored`). Every dataset exports its `provenance`.
- Kana IDs use the Hepburn reading; where two kana share a reading, the later one uses its Nihon-shiki spelling (ぢ → `di`, づ → `du`; ヂ, ヅ likewise). An extended katakana whose reading is already an ID uses the input-method spelling (ディ → `dhi`, ウォ → `who`). A kana ID names its script, so a hiragana and its katakana are separate items.
- Romaji is Hepburn. `alternatives` lists every other spelling practice accepts, and nothing more: Kunrei-shiki and Nihon-shiki spellings where they differ, `o` for を/ヲ, and `nn` for ん/ン. Extended katakana accept the input-method spelling where their Hepburn romaji is also another kana's (ティ `thi`, ディ `dhi`, ウォ `who`) and `sye`/`zye`/`tye` for シェ/ジェ/チェ, as the yōon accept `sya`/`zya`/`tya`.
- Kana are stored precomposed (NFC); romaji and alternatives are lowercase ASCII letters, the form answers are compared in. A dataset change keeps `kana-dataset.test.ts` passing; never loosen a validation rule to admit a record.
- Lesson IDs (`lesson.hiragana.ka`, `lesson.katakana.ka`) follow the same rule as item IDs: never renamed or reused, because lesson progress will refer to them. The part after the last dot is the lesson's URL.
- Content is text: never HTML or Markdown to be rendered as markup.
- Authored Japanese is reviewed by a fluent speaker before release; the pull request notes the review.
